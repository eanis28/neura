\hypertarget{dir_0701ad5d3ebfb3375b9ad2ef0e84b996_autotoc_md74}{}\doxysubsection{\texorpdfstring{Vim plugin usage}{Vim plugin usage}}\label{dir_0701ad5d3ebfb3375b9ad2ef0e84b996_autotoc_md74}
\doxylink{requirements_The}{The} vim plugin was designed to closely follow the mnemonics of vim

{\ttfamily s:\+spoken\+\_\+dict} is used to translate keys to their spoken form.

Keys corresponding to a string use that spoken value normally and when a motion is expected, but use the key itself when a character is expected. ~\newline
 Keys corresponding to a dict, like {\ttfamily i}, can have manual difinitions given to each possible commandset.

0 is normal (insert), 1 is motion (inside), 2 is it\textquotesingle{}s usage as a single key (\+[till]\+ i), and 3 is it\textquotesingle{}s usage in an area selection (s -\/\texorpdfstring{$>$}{>} \+[around]\+ sentence)

Some punctuation items, like {\ttfamily -\/} are explicitly given pronunciations to prevent them from being picked as punctuation instead of an actual command word.

Not all commands will tokenize to a single token and this can interfere with interpretation. "{}yank"{} as an example, takes multiple tokens and correspondingly, will give more accurate detection when only the first "{}ya"{} is used. While it could be changed to something else that is a single token (copy), value was placed on maintaining vim mnemonics.

Commands that would normally move the editor into insert mode (insert, append, open, change) will begin unguided transcription. Unguided transcription will end when a speech segment ends in exit. Presence of punctuation can be designated by whether or not you add a pause between the previous speech segment and exit. Exiting only occurs if exit is the last word, so "{}\+Take the first exit on your right"{} would not cause transcription to end.

After a command is evaluated, the plugin will continue listening for the next command.

While in command mode, "{}\+Exit"{} will end listening.

A best effort approach is taken to keep track of audio that is recorded while a previous chunk is still processing and immediately interpret it afterwards, but the current voice detection still needs a fairly sizable gap to determine when a command has been spoken.

Log information is sent to a special {\ttfamily whisper\+\_\+log} buffer and can be accessed with 
\begin{DoxyCode}{0}
\DoxyCodeLine{:e\ whisper\_log}

\end{DoxyCode}

{\ttfamily register\+Commandset} ~\newline
 {\ttfamily params} is a list of strings that should be checked for with this commandset. \doxylink{requirements_The}{The} server prepends a space to these strings before tokenizing. ~\newline
 Responds with ~\newline
 {\ttfamily result.\+index} an integer index for the commandset registered, which should be included when initiating a guided transcription to select this commandset. Will return an error if any of the commands in the commandset have duplicate tokenizations

{\ttfamily guided} ~\newline
 {\ttfamily params.\+commandset\+\_\+index} An index returned by a corresponding commandset registration. If not set, the most recently registered commandset is used. {\ttfamily params.\+timestamp} A positive unsigned integer which designates a point in time which audio should begin processing from. If left blank, the start point of audio processing will be the moment the message is recieved. This should be left blank unless you have a timestamp from a previous response. ~\newline
 Responds with ~\newline
 {\ttfamily result.\+command\+\_\+index} \doxylink{requirements_The}{The} numerical index (starting from 0) of the detected command in the selected commandset {\ttfamily result.\+command\+\_\+text} A string containing the command as provided in the commandset {\ttfamily result.\+timestamp} A positive unsigned integer that designates the point in time which audio stopped being processed at.
